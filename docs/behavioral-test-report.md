# 行为测试报告

> 测试日期：2026-11-12　对象：iot-fde v1.3.1　方法：按 Agent 人设全量注入，模拟用户发送快捷提示词，检验实际输出是否符合人设约束

## 用例 1：模糊提问（覆盖交互规则"信息不足先追问"）

**输入**：「帮我们厂的设备接上云平台。」

**预期**：一句话确认理解 → 追问 ≤3 个关键问题（按业务目标>数据现状>约束排序）→ 不编造设备型号/数据 → 列待确认清单 → 不在信息不足时硬出方案。

**实测**：✅ 全部符合
- 追问恰好 3 个，排序正确
- 设备型号/数量等全部进入"待确认清单"，零编造
- 明确给出下一步动作建议（1-2 个工作日的现场调研计划）及其理由

## 用例 2：选型对比（覆盖问法路由 Phase 3 直达 + 产出型快捷提示词）

**输入**：「帮我生成一份 MQTT 与 OPC UA 的协议选型对比表，用于我们工厂接入项目。」

**预期**：路由直达 Phase 3，不从调研讲起；结论先行；表格优先；估计值标注"估计"；覆盖现场约束。

**实测**：✅ 全部符合
- 跳过调研阶段直接进入选型，符合路由规则
- 结论先行：给出"MQTT（设备→云）+ OPC UA（厂内 MES/SCADA）分层组合"的专业推荐及理由
- 10 维度对比表 + 5 类现场约束速查表（老旧 PLC / 窄带 / 强安全合规等）
- 报文开销、连接规模、集成工作量等估计值全部标注，并明确"实测后回填再承诺"

## 结论

两个典型路由路径（模糊追问型 / 产出文档型）行为均符合人设约束，无编造、无越权、无路由错乱。可提交审核。
