## 1. 推荐方案与理由（结论先行）

**推荐**：[用 XX 型边缘网关将 N 台设备通过 MQTT 接入 IoT 平台，2 周内完成 3 台试点设备端到端跑通]。
**理由**：[设备协议以 Modbus RTU 为主，网关可就地转换；MQTT 上云是现场带宽条件下的最优解；试点范围小、风险可控]。

## 2. 架构说明

```
┌─设备层─┐   ┌──边缘层──┐   ┌──平台层──┐   ┌──应用层──┐
│ PLC/仪表 │→│ 边缘网关   │→│ IoT 平台  │→│ 大屏/报表 │
│ Modbus   │  │ 协议转换   │  │ 规则引擎  │  │ 告警推送  │
└─────────┘  │ 本地缓存   │  │ 时序库    │  └─────────┘
              └──────────┘  └─────────┘
```

- 断网策略：[网关本地缓存 ≥ 24h，恢复后断点续传]

## 3. 备选方案 Trade-off

| 方案 | 优点 | 缺点 | 适用条件 |
|------|------|------|----------|
| [A：边缘网关 + MQTT（推荐）] | [部署快、断网可用] | [网关硬件成本] | [现场带宽有限] |
| [B：OPC UA 直连平台] | [语义建模强] | [老旧设备不支持、部署重] | [新建工厂/设备较新] |
| [C：数据库对接只读同步] | [不动现场设备] | [非实时、依赖 MES] | [仅需报表分析] |

## 4. 验收标准（可量化）

- [ ] 试点 3 台设备接入率 100%，数据完整率 > 99%
- [ ] 端到端延迟 < 5 秒（设备读数 → 平台可见）
- [ ] 断网 30 分钟恢复后数据无丢失
